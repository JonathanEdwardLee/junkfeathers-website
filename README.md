# Junkfeathers Website

[![Astro Machine CI](https://github.com/JonathanEdwardLee/junkfeathers-website/actions/workflows/ci.yml/badge.svg)](https://github.com/JonathanEdwardLee/junkfeathers-website/actions/workflows/ci.yml)

Source for [junkfeathers.com](https://junkfeathers.com), the live static website for Junkfeathers music, Junkfeathers Tech, Orpheus Deck, and related creative work by Jonathan Edward Lee.

The site pairs a monochrome machine-inspired interface with a deliberately small, modern web stack. It is built for fast static delivery, narrow-screen usability, keyboard access, and straightforward maintenance.

## Site features

- Music and technology workshop indexes
- Orpheus Deck product information, full-resolution screenshots, and privacy policy
- Mobile-first layouts for phone, tablet, and desktop widths
- Static content with no application server or database requirement
- An intentionally disabled email module that collects no data
- Six generated routes with trailing-slash URLs

## Technology

- [Astro](https://astro.build/) with static output
- TypeScript in strict mode
- Semantic HTML and vanilla CSS
- Astro content collections
- npm lockfile for reproducible installs
- GitHub Actions for checks and production-build verification

No client framework is included. Browser JavaScript is kept to the minimum needed by the site.

## Mobile-first and accessibility principles

The interface is designed from narrow viewports outward. Components use fluid widths, wrapping layouts, responsive media, and square machine geometry without horizontal overflow. Interactive elements retain visible keyboard focus, semantic labels, adequate target sizes, and reduced-motion support. Decorative behavior must never obscure navigation or content.

## Local development

Requirements:

- Node.js `22.23.1` (also recorded in `.nvmrc` and `web/package.json`)
- npm

```bash
cd web
npm ci
npm run dev
```

Before submitting a change:

```bash
npm run check
npm run build
```

The generated static site is written to `web/dist/` and is intentionally excluded from Git.

## Repository map

```text
.github/workflows/   Continuous integration
docs/architecture/   Public architecture decisions
docs/assets/         Asset provenance notes
themes/              Preserved legacy WordPress theme source
web/public/          Static public assets
web/src/             Astro components, layouts, content, pages, and styles
```

The Astro application under `web/` is the current website runtime. The legacy theme is retained as source history and is not part of the Astro build.

## Continuous integration

The `Astro Machine CI` workflow runs clean dependency installation, Astro diagnostics, and a static production build for `main`, task branches, and pull requests. Pull-request builds are retained briefly as review artifacts. The workflow does not deploy the website.

## Branch model

- `main` contains reviewed website source.
- `production` contains generated static deployment output only.
- Hostinger must connect to `production`, not `main`.
- `production` is generated by automation and must not be edited manually.
